# 有记忆 vs 无记忆对比实验（M1001，两轮会话）

> 实验方式：同一个 Agent 连续执行两轮任务，唯一变量是是否挂载 `ShortTermMemory`。
> 模型 deepseek-v4-flash，`temperature=0`。结构化原始数据见 `memory_compare_with.json` / `memory_compare_without.json`。
>
> ```bash
> # 有记忆：多轮会话，记忆跨轮保留
> python agent/run_agent.py --member-id M1001 -i
> # 无记忆：同样的会话，但每轮互不感知上下文
> python agent/run_agent.py --member-id M1001 -i --no-memory
> ```

## 两轮任务

| 轮次 | 任务 |
|---|---|
| 第 1 轮 | 她问积分能不能转赠给家人？ |
| 第 2 轮 | 把刚才这个问题的结论写进回访日志 |

第 2 轮刻意写成**依赖上文**的指代式指令（"刚才这个问题"），用来检验 Agent 是否真的记住了上一轮。

## 对照结果

| 指标 | 有记忆 | 无记忆 |
|---|---|---|
| 第 1 轮推理步数 | 5 步 | 5 步 |
| **第 2 轮推理步数** | **2 步** | **4 步** |
| 第 2 轮工具调用 | 仅 `log_visit_result` | `query_member_profile`、`recall_member_history`、`search_knowledge_base` ×2、`log_visit_result`（全部重查一遍） |
| 第 2 轮能否理解"刚才这个问题" | 能 | 不能 |
| 日志备注内容 | 准确写入"积分不可转赠"的结论 | 未写入结论（改为重新核实身份） |

### 有记忆：第 2 轮直接落日志（2 步）

> 回访日志已记录完毕
>
> **会员编号：** M1001　**回访结果：** 已触达　**记录时间：** 2026-10-17 14:42
>
> **日志备注内容（本次咨询结论）：**
> - 会员咨询「积分能否转赠给家人」；
> - 已答复：积分与会员账户绑定，仅限本人使用，不可转赠他人（依据：积分规则 · 积分常见问题）；
> - 已提醒：账户 1250 积分将于 2026-12-31 到期清零，建议到期前本人使用；
> - 已告知：按当前 VIP 等级可享最划算的券「满 48 减 15」，可到店消费时一并使用；
> - 会员未提出其他诉求。
>
> 行动建议：下次回访时，可直接沿着这份记录确认会员是否已在到期前用掉积分，避免重复承诺同样的优惠。

落库记录为：

> 会员咨询积分能否转赠家人。已答复：积分与会员账户绑定，仅限本人使用，不可转赠他人（依据：积分规则 · 积分常见问题）；并提醒账户 1250 积分将于 2026-12-31 到期清零，建议到期前本人使用。同时告知当前 VIP 等级可享最优券「满 48 减 15」。会员未提出其他诉求。

Agent 没有重新查询任何信息，直接复用了上一轮的上下文。

### 无记忆：第 2 轮无法理解指代，拒绝编造（4 步）

> **说明一下：本次会话里我并没有拿到"刚才这个问题"的原始内容**，所以我不能凭猜测把某个结论写成正式回访记录。我先做了身份核验，并把能确认的信息登记为"待确认"，没有编造任何会员数据或政策。
>
> 已核实的会员情况（工具返回）：
> - 会员：李雪女士，VIP 等级，账户 1250 积分，到期日 2026-12-31
> - 历史回访记录（2026-10-17，共 3 条）全部是同一个问题——"积分能否转赠给家人"，并已多次据实答复
>
> 如果您说的"刚才这个问题"就是积分转赠，那么可以写进日志的结论如下（均已复核知识库，可直接引用）……
>
> **行动建议**：请您回一句确认"就是积分转赠那个问题"（或直接说明是哪条问题），我立刻把对应结论正式补记到 M1001 的回访日志里，替换掉当前的"待确认"记录。

Agent 重新走了一遍完整的信息获取流程（画像 → 历史 → 知识检索 ×2），并借助历史回访记录做了合理推测，但明确声明无法确认指代，要求用户确认后才写正式记录。

## 结论

1. **记忆不是"多存一段文本"，而是直接减少重复工具调用**：有记忆时第 2 轮只需 2 步，无记忆时需要 4 步，且后者获取的仍是"这类问题的通用答案"，无法还原上一轮的具体诉求。
2. **无记忆时的表现是安全的**：它没有编造结论，而是登记为"待确认"并请求用户确认，这验证了系统 Prompt 中"禁止编造"的约束生效；同时也说明短期记忆与长期记忆是互补关系——长期记忆（历史回访记录）能提供线索，但无法替代同一会话内的上下文。
3. 该对比可作为 `M2 工程化验收：有/无记忆对比可复现` 的证据；两轮对话在 `temperature=0` 下可重复执行。

## 复现说明

记忆跨轮保留的前提是**复用同一个 `ReActAgent` 实例**（其 `memory` 对象在多次 `run()` 之间累积）。CLI 的多轮模式已按此实现；单轮模式每次进程启动都会新建记忆，因此单轮任务之间不共享上下文，跨会话记忆依赖 `recall_member_history` 从日志中召回。
