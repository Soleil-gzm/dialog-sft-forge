## 3. 已具备能力

- 从 YAML、Excel 和案例文件加载生成任务输入，并由概率矩阵确定模块集合。
- 通过 FSM 约束模块路径，结合原子条件、条件组合、话术继承和促销策略生成多轮对话。
- 按任务组织生成产物，支持固定种子、路径缓存、检查点、单/多进程和可选分析。
- 通过 CLI 执行会员回访任务，模型调用可使用 OpenAI 兼容接口。
- Agent 可注册并调用会员档案、消费历史、库存、优惠计算、话术生成、结果落库等业务工具。
- 知识检索包含 BM25、可选 Embedding 向量路和 RRF；检索结果保留出处信息。
- Agent 离线评测：手写 YAML 评测集、规则评分、`agent/run_eval.py` 命令行，输出版本化 JSON/Markdown 报告并保留失败样本；`--mock` 模式可用 FakeLLM 无 Key 跑基线。
- 有 Agent 运行轨迹样例及生成器、Agent、知识工具、RAG 与评测模块测试。

## 4. 当前限制与风险

- `agent/data/mock_data.json` 是模拟数据，工具结果不代表真实业务系统数据。
- Embedding 服务未配置时是 BM25 单路检索，不能将该运行模式描述为已启用语义混合检索。
- NumPy 向量索引是内存实现，适合演示规模；没有 FAISS、持久化索引或生产级索引服务。
- 运行轨迹示例依赖当时的模型与配置；外部模型响应不保证逐字复现。
- 评测评分以规则判定为主：政策引用按答复中的「依据：」标注近似判断；「禁止编造」按 action 是否有 observation 回填近似判断；工具异常型失败与领域错误无法可靠区分，健壮性按注册表确定性错误标记近似计分。LLM 裁判接口已预留但未启用。
- 缺少端到端评测指标、真实业务数据治理、服务化部署和生产运维能力。
- 数据清洗增强与 Xtuner 的相关经验来自独立资产/个人实践，不属于当前仓库内已交付模块。

## 5. 下一步建议

1. 用真实 API Key 跑一次完整评测，核对失败样本与政策出处标注，视结果扩充评测集覆盖（多轮任务、歧义查询、并发工具调用等）。
2. 启用并校准 LLM 裁判（`--use-llm-judge`），对比规则分与质量分的差异，形成人工抽样复核流程。
3. 对生成结果定义 Schema 与质量校验，报告路径覆盖、条件命中、重复率和异常比例。
4. 记录真实训练方案、数据版本、模型权重来源和验证结果后，再将微调能力纳入项目交付范围。
5. 设计轨迹脱敏、筛选与回流准入规则，再实现与数据生成链路的自动衔接。
